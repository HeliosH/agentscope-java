## 三、缺口详解

### 3\.1 智能体的"聪明度"和控制

- **防死循环 \+ 自动判断完成**：QwenPaw 有一套可组合的"停止门控"——能检测智能体在重复动作（死循环）、能用 LLM 判断任务是否真完成、能按迭代次数/token 预算硬限；comac 只有简单的检查点取消，**没有这套门控**。

- **工作模式**：QwenPaw 能切"编码/目标/长任务"三种模式；comac **只有一种默认模式**。

- **多智能体**：QwenPaw 能运行时拉起多个子智能体分工；comac 的"多 Profile"只是**选不同角色**，子智能体开关默认关、没真正用起来（见 §五）。

- **外部智能体协作**：QwenPaw 通过 ACP 协议既能把自己暴露给外部智能体用、也能把活派给外部智能体（Qwen Code、Claude Code 等）；comac **没这套**。

### 3\.2 记忆和上下文

- **长对话翻回查**：QwenPaw 把完整历史存下来、还能按需召回（甚至写代码去历史库里查）；comac 只做简单压缩，**长会话早期内容查不回**。

- **长期记忆**：QwenPaw 有本地\+远程多层记忆，能自动把对话沉淀成笔记、自动整理记忆、空闲时主动找你聊；comac **没有跨会话记忆、不会主动**。

### 3\.3 工具和扩展

- **工具数量**：QwenPaw 自带 22 个工具（浏览器自动化、网页搜索/抓取、代码 AST/LSP、截图、多媒体、批处理等）；comac 主要复用框架自带的几个（读文件、执行命令），**没有浏览器、网页搜索、代码理解**。

- **工具控制**：QwenPaw 的工具调用能精细控制超时、取消、转后台；comac 粒度粗。

- **技能系统**：QwenPaw 有完整技能市场和管理（像装 App）；comac **只能上传 zip 注册**，没有提示词生命周期管理。

- **插件**：QwenPaw 能装/卸插件扩展；comac **必须改代码**。

### 3\.4 模型和外部连接

- **多模型管理**：QwenPaw 能管多个模型供应商、自动重试、限流、一个挂了切另一个；comac **只调一个兼容接口、不会自动救**。

- **接外部工具**：QwenPaw 接外部能力有统一抽象（能接 MCP 也能接别的）；comac **只能走 MCP**。

- **接外部工具的安全**：QwenPaw 有 OAuth 授权、密钥加密、访问审批策略；comac 偏身份透传（且 token 明文拼进 prompt 的已知隐患）。

### 3\.5 安全

QwenPaw 安全做得深：工具调用前扫参数（防命令注入/数据外泄）、技能安装前扫威胁、分四档风险审批、有操作审计日志、密钥加密存。 comac 只有：删命令要审批 \+ 目录越界拒绝。**没有参数扫描、没有技能扫描、没有审计、密钥明文存**——这是不限定位、任何后端都该有的短板。

### 3\.6 自动化和运维

QwenPaw 有：定时任务、心跳、主动唤醒、备份恢复、token 用量统计、内网穿透、CLI 诊断、LLM 可观测平台。 comac：基本没有用户态定时任务、没备份恢复、没用量统计、没隧道、没 CLI 诊断。

### 3\.7 复杂任务显式拆解

QwenPaw 通过 Mission 模式具备结构化复杂任务拆解、进度持久化和状态展示能力；comac\-agent 可以输出思考过程和工具进度，但默认工具列表中没有创建计划、更新任务状态或查询计划的通用工具，因此尚未提供框架级的通用任务拆解、任务状态管理和计划展示能力。

## 六、缺口与 comac 定位的关系（结论）

- 上表 17 类缺口**多数是 comac "B 端被集成后端"定位的自然结果**——它不需要做 C 端助理的 Coding/Mission/频道/隧道等，所以不算"缺陷"。

- 但有**几类与定位无关、属于通用后端该有的能力**，建议优先关注：

    - **安全治理**（参数扫描 / Skill 扫描 / 凭据加密 / 审计）——comac 凭据明文 \+ 无前置扫描，是实打实的安全隐患（不限定位）。

    - **模型调用韧性**（重试 / 限流 / 故障回退）——任何后端都该有。

    - **任务门控**（至少防死循环 \+ 完成度判定）——避免 agent 空转。
